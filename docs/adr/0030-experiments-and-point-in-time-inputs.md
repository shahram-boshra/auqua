# 0030. Experiments and point-in-time inputs

Date: 2026-10-21

## Status

Accepted

## Context

A research result is only as trustworthy as the record of what produced it and the guarantee that it used no information from its future. The walking skeleton read bars from the log in log order and recorded only hashes of its inputs.

## Decision

Every run starts with a `research.run.v2` record (skeleton `v1` records are upcast): hypothesis, specification version, periods, bar interval, the input snapshot (log head and its knowledge time), every input source with its profile, terms, use class, jurisdiction, availability basis and a digest of its raw files, the seed, the code identity, the Python version and the SHA-256 of the lock file. Runs read market data only through a point-in-time snapshot: the input log up to its head, revisions resolved at the snapshot's knowledge time, bars released at their availability time, and the log clock advanced to that time. A run refuses an input without a source profile, not cleared for the operator's jurisdiction or not permitting backtests, and refuses ambiguous series (several intervals or sources) unless the specification names one. Data generated by the operator is a first-party source with no third-party terms.

## Consequences

Look-ahead is excluded by construction, not by strategy code. A correction ingested after a run is invisible to a rerun pinned to the run's input record count (`input_records`, recorded in the run and the report) and visible to a new snapshot. Reports can always say which data, under which terms, produced a result.
